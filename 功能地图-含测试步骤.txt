TWM Launcher 功能地图 — 含测试步骤
================================================================

1.欢迎页
────────────────────────────────────────────────────────

1.1 游戏路径选择
  成功 → 弹出文件夹选择窗口，选择包含 "The Scroll of Taiwu.exe" 的目录后进入主界面
  成功 → 消息栏显示"游戏目录已就绪"
  失败 → 1.1.1 无效路径：红色错误提示"[所选目录]未找到 The Scroll of Taiwu.exe，请确认选择了正确的游戏根目录"
  失败 → 1.1.2 取消选择：停留在欢迎页，不进入主界面
  未覆盖 → 所选路径无读取权限（如 C:\Windows）→ 当前无独立处理
  未覆盖 → 路径在移动磁盘上、选择后磁盘被拔出 → 当前未处理

  测试步骤：
    1. 启动应用 → 显示欢迎页，提示"请选择游戏目录"
    2. 点击选择 → 选择正确的游戏根目录 → 进入主界面，消息栏显示"游戏目录已就绪"
    3. 点击选择 → 选择不含 exe 的目录 → 红色错误提示包含完整路径
    4. 点击选择 → 取消选择 → 停留在欢迎页
    5. 选择移动磁盘中的路径 → 弹出磁盘 → 观察是否提示路径不可用（预期：无提示）
    6. 选择无读取权限目录（如 C:\Windows\System32）→ 观察是否有权限提示（预期：无独立提示）

1.2 重新选择（工具栏按钮）
  成功 → 跳转回欢迎页，弹出文件夹选择窗口
  未覆盖 → 当前已选择路径后磁盘被拔出 → 重新选择时原路径不可用，当前无处理

  测试步骤：
    1. 在主界面点击"重新选择"按钮 → 跳转回欢迎页 → 弹出文件夹选择窗口
    2. 选择新的有效路径 → 进入主界面，Mod 列表更新
    3. 选择无效路径 → 红色错误提示
    4. 取消选择 → 停留在欢迎页（gamePath 为空）

1.3 启动时自动恢复缓存路径
  成功 → 上次选择的游戏路径持久化到 config.json，下次启动自动验证并恢复
  失败 → 缓存的路径已失效（目录删除/磁盘拔出）→ 显示"缓存的游戏路径已失效，请重新选择游戏目录"，回退到欢迎页

  测试步骤：
    1. 选择游戏路径 → 关闭应用 → 重新打开 → 自动进入主界面，消息栏显示"游戏目录已就绪"
    2. 选择游戏路径 → 关闭应用 → 手动删除该目录 → 重新打开 → 显示"缓存的游戏路径已失效"，停留在欢迎页
    3. 首次启动（无缓存）→ 直接显示欢迎页
    4. 手动清空 config.json → 启动 → 正常显示欢迎页

2.Mod 列表
────────────────────────────────────────────────────────

2.1 Mod 及配置读取
  成功 → 扫描游戏目录，解析 Config.lua 生成 Mod 卡片列表
  成功 → 显示 Mod 封面、标题、作者、版本、游戏版本、标签
  失败 → 目录内无 Mod → 列表区域为空，消息栏显示"共 0 个 Mod"
  失败 → 部分 Mod 解析失败 → 加载其余 Mod，消息栏显示失败数量和名称（最多 3 个 + "等 N 个"）
  失败 → 扫描过程致命错误（如目录被删除）→ 显示"刷新失败，请检查游戏目录是否可用"
  未覆盖 → Mod 目录无读取权限 → 当前未独立处理

  测试步骤：
    1. 选择有效游戏目录 → 验证 Mod 列表加载，每个卡片信息正确
    2. 选择无 Mod 的目录 → 验证列表为空，消息栏显示"共 0 个 Mod"
    3. 在 Mod 目录中放入一个 Config.lua 损坏的 Mod → 验证该 Mod 被跳过，消息栏列出失败名称
    4. 放入多个损坏 Mod → 验证失败列表截断显示（前 3 个 + "等 N 个"）
    5. 扫描完成后删除游戏目录 → 点击刷新 → 验证显示"刷新失败"提示
    6. 首次扫描时验证 ModSettings.Lua 解析结果反映在启用状态中

2.2 Mod 配置页 (SettingsEditor)
────────────────────────────────────────────────────────

2.2.1 修改数量提示
  成功 → 标题栏显示"N 项已修改"
  失败 → 未做任何修改时计数为 0，"保存"按钮隐藏

  测试步骤：
    1. 打开 Mod 配置页 → 初始计数 0，"设置"标题显示，保存按钮不可见
    2. 修改一个下拉项 → 计数变为 1，"保存"按钮出现
    3. 修改多个项 → 计数正确累加
    4. 将值改回原值 → 验证计数/按钮状态（看是否检测净变化 vs 累计变化）

2.2.2 配置内容
────────────────────────────────────────────────────────

2.2.2.1 下拉栏
  成功 → 选中值即时更新，修改计数 +1
  未覆盖 → 下拉选项为空（Config.lua 未定义可选值）→ 应显示空下拉并提示，当前未处理

  测试步骤：
    1. 打开含下拉配置的 Mod → 切换选项值 → 验证即时更新和计数变化
    2. 修改后关闭配置页（不保存）→ 重新打开 → 验证值是否已恢复原值
    3. 如果一个 Mod 的 Config.lua 定义了空选项列表 → 编辑下拉 → 验证表现

2.2.2.2 开关
  成功 → 切换立即响应，修改计数 +1

  测试步骤：
    1. 切换 Boolean 开关 → 验证即时响应
    2. 多次快速切换 → 验证计数始终正确

2.2.2.3 滑块
  成功 → 拖动即时响应，数值实时显示，修改计数 +1
  未覆盖 → 滑块值超出 Config.lua 定义的 min/max 范围 → Config.lua 约束，边界情况未验证

  测试步骤：
    1. 拖动滑块 → 验证数值实时显示
    2. 拖到极值 → 验证限制在 min/max 范围内
    3. 修改后关闭不保存 → 重新打开 → 验证恢复原值

2.2.3 导航（设置分组列表）
  成功 → 点击分组名切换右侧设置项
  未覆盖 → Config.lua 中 GroupName 缺失或为空 → 当前未处理

  测试步骤：
    1. 打开有多分组的 Mod → 点击不同分组名 → 验证右侧设置项切换
    2. 分组列表滚动 → 验证高亮指示器跟随
    3. 检查 GroupName 为空的 Mod → 验证侧栏导航显示

2.2.4 关闭
  成功 → 返回 Mod 列表
  失败 → 有未保存修改时关闭 → 弹窗确认"有 N 项未保存，是否放弃？"，选"放弃"则丢弃修改，选"取消"则留在配置页

  测试步骤：
    1. 打开配置页 → 不做修改 → 关闭 → 直接返回列表
    2. 修改几项 → 不保存 → 关闭 → 弹出确认对话框显示正确数量 → 点击"放弃"→ 返回列表，修改丢弃
    3. 同上 → 点击"取消"→ 留在配置页
    4. 修改 → 保存 → 关闭 → 直接返回列表（无弹窗）

2.3 分组卡片
────────────────────────────────────────────────────────

2.3.1 创建分组
  成功 → 新分组出现在列表中，默认展开，默认名称为"新建分组"

  测试步骤：
    1. 点击新建分组 → 分组出现，名称为"新建分组"
    2. 创建多个分组 → 验证顺序和默认命名
    3. 右键 Mod → 发送到分组 → 新分组创建 → 验证 Mod 归入

2.3.2 拖拽移动整组
  成功 → 分组顺序改变，蓝色插入线指示目标位置

  测试步骤：
    1. 拖拽分组头部 → 验证蓝色插入线显示
    2. 拖到另一个分组上方/下方 → 释放 → 验证顺序改变
    3. 拖拽到列表顶部/底部 → 验证边界处理
    4. 嵌套分组拖拽 → 验证层级变化

2.3.3 归入/移出 Mod 卡片
  成功 → Mod 移入/移出分组，缩进变化

  测试步骤：
    1. 拖拽未分组 Mod 到分组内 → 验证缩进变化
    2. 从分组拖出 Mod → 验证回到未分组状态
    3. 在分组间移动 Mod → 验证目标分组正确

2.3.4 收起/展开内容
  成功 → 分组内 Mod 隐藏/显示

  测试步骤：
    1. 点击分组收起箭头 → 验证子 Mod 隐藏，箭头方向变化
    2. 再次点击 → 验证展开，子 Mod 重新显示
    3. 收起分组后拖拽 Mod 到分组上 → 验证自动展开或拒绝

2.3.5 取消分组
  成功 → Mod 回到未分组状态，分组消失（如果为空）

  测试步骤：
    1. 右键分组 → 取消分组 → 验证所有子 Mod 回到未分组状态
    2. 分组中只有一个 Mod → 取消分组 → 验证分组消失

2.3.6 删除分组
  成功 → 弹确认框，确认后分组消失，分组内 Mod 回到未分组状态

  测试步骤：
    1. 右键分组 → 删除 → 验证弹出确认对话框
    2. 点击确认 → 验证分组消失，子 Mod 回到未分组状态
    3. 点击取消 → 验证分组保持不变
    4. 删除嵌套分组 → 验证子分组和 Mod 都回到未分组

2.3.7 重命名
  成功 → 分组名更新
  成功 → 输入为空（或全空格）→ 自动使用默认名称"未命名分组"

  测试步骤：
    1. 右键分组 → 重命名 → 输入新名称 → 回车 → 验证名称更新
    2. 清空名称后回车 → 验证自动变为"未命名分组"
    3. 输入全空格后回车 → 验证自动变为"未命名分组"
    4. 输入超长名称 → 验证 UI 表现
    5. 编辑中按 Escape → 验证保持原名不变

2.3.8 右键菜单
  成功 → 提供重命名、取消分组、删除分组操作入口

  测试步骤：
    1. 右键分组 → 验证菜单项完整（重命名/取消分组/删除）
    2. 逐一执行各项操作 → 验证功能正确

2.4 Mod 卡片
────────────────────────────────────────────────────────

2.4.1 拖拽移动卡片
  成功 → Mod 顺序改变，出现蓝色插入线指示位置

  测试步骤：
    1. 拖拽 Mod 到列表不同位置 → 验证蓝色插入线
    2. 拖到分组内 → 验证归入该分组
    3. 拖到列表顶部/底部 → 验证自动滚动
    4. 在分组内上下拖拽 → 验证组内排序

2.4.2 启用开关
  成功 → 开关立即切换，标记 isDirty，消息栏更新
  失败 → 写盘失败（同步按钮）→ 开关弹回原状态，消息栏显示"保存失败: [错误信息]"

  测试步骤：
    1. 切换一个 Mod 的开关 → 验证立即生效，工具栏"同步"按钮高亮
    2. 点击"同步"→ 验证写盘成功，消息栏显示"已保存"
    3. 选中 Mod → 切换开关 → 立即点"同步"→ 选中 Mod 标题栏有绿色/灰色状态指示

2.4.3 加载顺序
────────────────────────────────────────────────────────

2.4.3.1 手动输入
  成功 → 输入数字后回车/失焦，顺序更新
  失败 → 输入非数字字符 → 自动恢复原值
  失败 → 输入为空 → 自动恢复原值
  失败 → 输入负数 → 自动恢复原值

  测试步骤：
    1. 在顺序输入框输入"5"→ 失焦 → 验证值为 5 且标记 isDirty
    2. 输入"abc"→ 失焦 → 验证恢复原值
    3. 清空输入 → 失焦 → 验证恢复原值
    4. 输入"-1"→ 失焦 → 验证恢复原值
    5. 输入"00123"→ 失焦 → 验证去前导零后为 123
    6. 输入"3.7"→ 失焦 → 验证 floor 为 3

2.4.3.2 加减按钮
  成功 → 点击 ▲+1 / ▼-1，顺序更新
  失败 → 减至负数 → 不执行减操作

  测试步骤：
    1. 对 order=5 的 Mod 点击 ▲ → 验证变为 6
    2. 对 order=0 的 Mod 点击 ▼ → 验证不变化（不变成负数）
    3. 快速连续点击 ▲ 5 次 → 验证正确累加

2.4.3.3 应用顺序
  成功 → 所有已启用 Mod 按显示顺序重排为 0,1,2...，嵌套分组内独立排序

  测试步骤：
    1. 在 Mod 列表随机修改几个 order 值 → 点击"应用顺序"
    2. 验证所有已启用 Mod 的 order 从 0 开始连续排列
    3. 存在分组 → 验证每个分组内独立排序
    4. 有未启用的 Mod → 验证它们的 order 不受影响

2.4.4 信息显示
  成功 → 详细模式：封面图、标题、作者、版本、游戏版本、描述、标签、更新日期
  成功 → 紧凑模式：缩略封面、标题、作者、启用开关、顺序输入

  测试步骤：
    1. 查看详细模式卡片 → 验证所有字段正确显示
    2. 无封面的 Mod → 验证显示默认占位图
    3. 切换紧凑模式 → 验证布局变化

2.4.5 打开 Mod 本地目录
  成功 → 在资源管理器中打开 Mod 文件夹
  失败 → 目录不存在 → 弹出错误对话框 "目录不存在: [路径]"

  测试步骤：
    1. 点击"打开目录"或右键 → 在资源管理器中打开 → 验证指向正确的 Mod 目录
    2. 手动删除 Mod 目录后 → 点击打开目录 → 验证弹出错误提示"目录不存在"

2.4.6 访问创意工坊
────────────────────────────────────────────────────────

2.4.6.1 浏览器
  成功 → 在默认浏览器中打开 Steam 工坊页面
  忽略 → 网络不可用 / 默认浏览器未设置 → 浏览器/操作系统自行处理

  测试步骤：
    1. 右键工坊 Mod → "在浏览器中打开工坊页面"→ 验证浏览器打开正确 URL
    2. URL 格式应为 https://steamcommunity.com/sharedfiles/filedetails/?id=FILEID

2.4.6.2 Steam 客户端
  成功 → 启动 Steam 客户端并跳转到工坊页面
  失败 → Steam 未安装 → 弹出错误对话框 "未检测到 Steam 客户端"

  测试步骤：
    1. 右键工坊 Mod → "在 Steam 中打开"→ 验证 Steam 客户端打开（如已安装）
    2. 未安装 Steam 的机器上 → 验证弹出错误提示
    3. Steam 已安装但未运行 → 验证是否能正常唤起

2.4.7 右键菜单
  成功 → 提供开关/打开目录/工坊访问/归入分组操作
  失败 → 当前无分组时 → "快速归并分组"按钮置灰（灰色 + 不可点击）

  测试步骤：
    1. 右键 Mod 卡片 → 验证菜单项完整
    2. 无分组存在时 → 验证"发送到"按钮置灰且 hover 不展开子菜单
    3. 有分组时 → 验证"发送到"hover 展开子分组列表 → 点击 → Mod 归入目标分组
    4. 逐一执行各菜单项 → 验证功能正确

2.5 简略/详细切换
  成功 → 卡片布局在详细模式和紧凑模式之间切换

  测试步骤：
    1. 点击紧凑/详细切换按钮 → 验证所有卡片布局变化
    2. 紧凑模式下 → 验证顺序输入框和开关仍然可用
    3. 详细模式下 → 验证封面、描述、标签等字段显示

2.6 卡片拖动到视口边缘
  成功 → 拖拽卡片到列表边缘时自动滚动

  测试步骤：
    1. 创建足够多的 Mod 使列表出现滚动条
    2. 拖拽卡片到列表顶部边缘 → 验证自动向上滚动
    3. 拖拽到列表底部边缘 → 验证自动向下滚动

2.7 刷新
  成功 → 重新扫描 Mod 目录，列表更新
  失败 → 有未保存更改时刷新 → 弹窗确认"刷新将丢弃未保存的更改，确定继续吗？"
  失败 → gamePath 无效（目录已删除）→ 验证路径 → 无效则显示"游戏目录不可用，请重新选择"并跳转欢迎页
  失败 → 刷新过程中有 Mod 解析失败 → 成功加载其余 Mod，消息栏列出失败名称

  测试步骤：
    1. 有未保存更改 → 点击刷新 → 验证确认弹窗 → 取消 → 保持当前状态
    2. 同上 → 确认 → 重新扫描，修改丢弃
    3. 无未保存更改 → 点击刷新 → 直接重新扫描
    4. 点击刷新前删除游戏目录 → 模拟刷新 → 验证跳转欢迎页并提示
    5. 放入部分损坏 Mod → 刷新 → 验证成功 Mod 正常加载 + 失败 Mod 名称提示

3.筛选
────────────────────────────────────────────────────────

3.1 搜索
  成功 → 模糊匹配名称/作者/描述，实时过滤列表
  失败 → 无匹配结果 → 列表为空

  测试步骤：
    1. 在搜索框输入 Mod 名称片段 → 验证实时过滤
    2. 搜索作者名 → 验证该作者的所有 Mod 显示
    3. 搜索描述关键词 → 验证匹配的 Mod 显示
    4. 输入不存在的关键词 → 验证列表为空
    5. 清空搜索框 → 验证恢复完整列表

3.2 全部/启用/禁用
  成功 → 三态切换，过滤列表

  测试步骤：
    1. 点击"启用"筛选 → 验证只显示已启用的 Mod
    2. 点击"禁用"筛选 → 验证只显示禁用的 Mod
    3. 点击"全部" → 验证所有 Mod 显示
    4. 结合其他筛选条件 → 验证交叉过滤正确

3.3 本地/工坊 残留/正常
  成功 → 多选过滤，交集生效
